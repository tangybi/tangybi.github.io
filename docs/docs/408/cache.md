# 缓存

缓存可以按位置、内容和生命周期三个维度来分，从浏览器加载一个网页的完整过程这个角度来梳理，会很清晰。

## 按“数据在哪里”分（核心分类）

数据越靠近用户端，访问就越快。

### 浏览器缓存

私有缓存，仅为当前浏览器服务，是最快、最私密的一级。
- 内存缓存：页面关闭即失效，极快。

- 磁盘缓存：持久保存，下次打开浏览器仍有。

- DNS 缓存：你之前问的 Edge/Safari 内部缓存就属于这里。 

> [!TIP] Chrome
> :earth_asia: chrome://net-internals/#dns.

> [!TIP] Edge
> :earth_americas: edge://net-internals/#dns。Edge 浏览器自己有一套独立的 DNS 缓存机制，它不直接依赖系统缓存，而是会维护自己的“内部电话本”来加速网页访问。不过，为了防止“电话本”里的号码过时导致网页打不开，通常浏览器缓存的生存时间都很短，一般在 1 到 5 分钟左右。

> [!TIP]   Safari
> :earth_africa: DNS缓存约10秒。隐私优先 “智能防跟踪” 功能。 “防止跨站跟踪” 不为第三方域名保留长时间的 DNS 缓存，或用完即丢，让追踪者难以将你的多次访问关联起来。

- Service Worker：开发者可控的智能缓存，能实现离线访问。


### 本地/操作系统缓存

供本机上所有应用共享。
- 系统 DNS 缓存： ipconfig /displaydns/nslookup/dig。
- hosts 文件：也可以看作一种静态、手动的本地 DNS 缓存。
- WebView 缓存：微信等 App 内嵌浏览器的缓存。

### 网络中间件缓存

为局域网或特定区域的大量用户服务。(共享缓存)
- 代理服务器缓存：公司、学校常部署，节省出口带宽。
- CDN 边缘节点缓存：网站静态资源（图片、JS文件）通常已被缓存到离你最近的节点。它的 DNS 调度机制，就和你之前关注的 CDN 调度直接相关。


## 按“缓存的是什么”分

这决定了缓存具体存了哪类东西。
- DNS 记录缓存.域名与 IP 的对应关系.
- HTTP 内容缓存.网页的原始资源，可能是压缩的。
- 程序/计算缓存.需要消耗 CPU 才能得到的结果，避免重复计算。
- 页面/渲染缓存.浏览器对已渲染页面的记录。

## 按“数据生命周期”分

这关系到缓存什么时候会被丢弃。
- 强缓存 (Freshness)在有效期内直接使用，根本不问服务器。由 Expires / Cache-Control: max-age 字段控制。
- 协商缓存 (Validation) 每次都会问服务器该资源能否复用，由服务器决定返回 304 (Not Modified) 还是新数据。由 Last-Modified / ETag 等字段控制。

| 缓存类型 | 核心区别 | 面向对象 | 存储位置 | 生命周期 | 典型场景 |
|------|------|------|------|------|------|
| 浏览器缓存 (HTTP Cache) | 浏览器自动管理，开发者只能通过配置Cache-Control等HTTP头来建议浏览器行为。 | 浏览器引擎 | 内存 + 磁盘	 | 由 HTTP 头 (max-age, Expires) 和浏览器策略共同决定。 | 访问的图片、CSS、JS文件，浏览器自己决定是否缓存、用内存还是磁盘。 |
| sessionStorage (Web Storage API) | 开发者主动调用的JS API (sessionStorage.setItem())。 | 网页开发者 | 仅内存 | 页面会话期间有效。关闭标签页或浏览器，数据即清空。 | 保存表单临时数据、单次会话的状态，刷新页面不丢失，但关闭再打开就没了。 |
| CacheStorage (Cache API) | 开发者主动调用的JS API (caches.open())。 | 网页开发者 | 磁盘 | 完全由开发者控制，可长期持久化保存。 | 实现离线访问的利器。Service Worker 常用来预缓存 App Shell 和核心资源。 |
